# leads-demo

Демо-витрина: как квалифицировать входящие заявки сервисной компании, не гоня каждую в модель.

За день падает пачка заявок из формы, WhatsApp и Instagram. Дешёвые правила
(спам, нет предмета, дубль, вне зоны, не наша услуга, ниже минимума, выезд
вне смены без доплаты) снимают очевидное бесплатно. Модель смотрит только
выживших и раскладывает: к менеджеру, ссылка на календарь, в рассылку,
вежливый отказ. Спорные (нет уверенности или цитата не из текста) - отдельно
человеку. У каждого отказа по правилу есть имя правила и цитата из текста.
Пороги правятся на странице.

Компания вымышленная (Bayline Comfort Co., Port Meridian). Людей в данных нет.

## Запуск

```bash
./app.py              # http://127.0.0.1:8080  (uv ставит зависимости сам)
./app.py --selftest   # механика и сборка, без вызова модели. Падает, если правила сломаны
./app.py --record     # записать мнения модели в data/judgments.json (редко, не со страницы)
```

Ничего ставить руками не нужно. Python 3.11+ и `uv`.

## Где что менять

- Пороги на странице, либо дефолт в `data/business.json`
- Пачка заявок - `data/requests.json` (оставьте синтетику)
- Записанный прогон модели - `data/judgments.json`
- Промпт модели и прейскурант - `app.py`

Кнопка на странице не зовёт модель: механика считается живьём, мнения
подставляются из записи. На странице это сказано. Модель: Vertex на
trial-кредитах, фолбэк `GEMINI_API_KEY_FREE` из `~/Projects/.env.local`.
OpenRouter не используется.
